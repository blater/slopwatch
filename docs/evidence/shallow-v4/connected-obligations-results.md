# Connected obligations correction

This correction retains the numeric publication, uncertainty, safety and previous
acceptance requirements. Production weights and previously frozen expectations
are unchanged. The prior observed holdouts are development regression evidence;
new high-band source selection is separate and frozen before evaluation.

## Diagnosis

Package-visible representation was excluded by a public-only field filter. Caller
coupling considered only target-body statements, missing obligations split between
external operations. Scoped receiver typing and inherited declaring storage are
needed to connect those operations without using field spellings as identity.

The frozen BoundAccess caller witness refers to subclasses whose inheritance
declarations are absent from the witness-only input. Full workspace analysis has
those declarations; the witness-only run cannot safely assume their ancestry.
Keep isolated, retained-witness and full-workspace results distinct.

Callback execution, same-value creation/attachment/caching, output-connected
projection and independent cleanup attempts need connected-effect evidence.
Known library contracts may establish invocation and cleanup behavior only when
the receiver resolves to the declared library type; method spelling alone is not
proof of that contract.

The Boolean recognizer hard-coded acquisition=true and restoration=false. The
correction must track opposite states on the same storage and connect the guarded
branch to admission, preserving rejection of intervening reset or replacement.
Review additionally reproduced reversed admitting branches and release-before-use.

Rust restricted audience was treated as private during root selection: same-file
test callers suppressed the real pub(crate) entry point. A production boundary's
existence must not depend on whether unit tests happen to call it.

- Keep all 60 synthetic and 12 real frozen criteria, the separate exact xmltoaster

- Evaluate the original Java holdout in isolated, retained-witness and full live

  ap/warren baselines, alongside Java workspace and current repository coverage.

## Evidence scope

Caller-field analysis covers scoped same-package Java declarations and bounded
inheritance. It connects shared data, guarded mode selection and externally split
state phases. Imported or incomplete hierarchies and arbitrary interprocedural
write splitting are not fully resolved. Unobserved package caller obligations
remain explicit limitations.

Buffer effects cover supported Rust Vec, TypeScript array and Go indexed-write
contracts and bounded private helpers. Ordered aliases preserve effects before a
later rebind and exclude mutations of replacement buffers. Typed local shadows
and uninvoked callable bodies are distinct from caller storage. Arbitrary
higher-order callbacks remain unsupported.

Map credit establishes retained factory/cache behavior, including resolved helper
extraction; it does **not** claim attachment semantics for an unresolved method
such as parent.addNode. JDBC recognition covers constructor-supplied typed
resources with independently handled declared SQL failure paths. Projection is
explicitly estimated when getter aliasing or element mutation is unresolved and
shares, rather than duplicates, the transformation envelope.

Independent review supplied executable counterexamples for polarity/branch
orientation, intervening release, qualified receiver/source reassignment, dead
and disconnected effects, type shadowing/import precedence, catch declarators,
constructor RHS identity, projection disconnects and scoped output aliases.
Corrections retain regression tests for those cases.

## New high-band evaluation and remaining gaps

The independently selected six-case corpus contains one reviewed high and one
reviewed low example per language. All target and caller-witness bytes and labels
were frozen before scoring. The selector had prior scorer-source exposure,
explicitly disclosed in `connected-high-holdout/selection.md`; selection was blind
to candidate scores, not fully blind to the model.

Its immutable first evaluation produced Go **25 / 3**, TypeScript **0 / 20** and
Rust **79 / 43** (high / low). Only three of six bands and one of three rankings
passed. Frozen caller context produced the same failures. This first evaluation
is retained unchanged; subsequent corrections make this corpus development
evidence and do not constitute a new independent validation.

Inspection revealed that the apparent Rust high-band pass attributed generic
binder `T` as the owner instead of `ManuallyDrop`; the low example similarly used
lifetime `a` instead of `Drain`. The corrected parser resolves nominal impl owners
through generic, trait and where syntax. A numeric band hit with the wrong
boundary is not evidence of correct positive detection.

Go capability forwarding was incorrectly counted as representation conversion.
Bounded dispatch recognition now preserves actual capability checks while
excluding unchanged argument/result forwarding from conversion credit. Equivalent
checks deduplicate only for the same stored receiver and tested capability;
different capabilities remain different duties. The corrected Go example still
scores 28: returned connection/buffer ownership and lifecycle split across its
callers are not yet represented by the Go surface index. Five distinct capability
checks are retained; collapsing them solely to reach the reviewed high band would
be another calibration error.

TypeScript roots that mutate/read the same declared private module storage now
form a connected boundary. Scope-aware helper result flow excludes discarded
reads. Private scalar state retains the same duties as class storage. The registry
therefore has one boundary with state responsibility 2 and score 20; recognizing
its boundary does not justify erasing useful bookkeeping to reach a high band.
The graph does not yet carry token identity through creation, insertion, return,
caller retention and deletion. An add/delete-name heuristic would not solve that.

Follow-up measurements, sensitivity and wide-coverage results are recorded below
after the final correction. No high-band failure permits changing the frozen
labels or choosing production weights to fit these examples. These failures leave
cross-language empirical readiness open. They also prevent claiming that all of
the latest requested acceptance has been achieved.



### Remaining Go caller-flow work

A source review of the retained reverse-proxy witness identifies a feasible next
proof: resolve `http.NewResponseController` through its imported package and return
type; bind the result slots of the controller call; trace the returned `net.Conn`
to deferred contract cleanup, and the returned `*bufio.ReadWriter` to response
serialization followed by checked flushing. Receiver/result aliases, reassignment,
shadowing and failure branches must be resolved before attributing an obligation.
Deduplicate by callee/result storage, not the number of callers or familiar method
names. Timer callbacks, goroutine coordination and caller-owned deadline semantics
need broader flow support. This diagnosis is not implemented evidence and does not
turn the retained Go high-band failure into a pass.
